# ml/ — layer rules

The worker process: one thread per active camera plus a supervisor. Owns frame acquisition (RTSP via an ffmpeg pipe with a stream-copied local HLS tee; the HLS VOD reader with AES-128 decrypt; the local replay source), the time base, the motion gate, the detector, the tracker, OCR, plate normalisation, sighting persistence, the cached watchlist match, object and zone events, and the stats snapshot. Reads the root `CLAUDE.md` first; these rules add to it. **Read `docs/feed-rules.md` and `docs/sandbox-findings.md` in full before writing a frame source.**

## Rules that bite this layer

- **The nine required behaviours of the frame source** (`docs/feed-rules.md`, last section) are the acceptance test: transport from the registry; credentialed URL built in memory, email percent-encoded, never logged unmasked; `(frame, pts_ms, wall_clock_utc)` tuples; sampling by dropping on PTS, never by sleeping; inter-frame gaps tolerated; decoder warnings at DEBUG; jittered backoff `2 s · 2^n · random(0.5, 1.5)` capped at 30 s with the anchor reset on reconnect; loop discontinuity → `stream_restart`; capture released in `finally`. The previous build's four checks (P2.1 in `docs/reference/old-build/P2-anpr.md`) still apply: 100 monotonic frames; ~180 frames in 60 s at 3 fps with a ~60 s PTS span; reconnect with visibly growing jittered delays; join warnings logged, loop continues.
- **One pull per camera** — the live wall is served from this process's tee, never a second connection. Active tier ≤ 6 until the RTSP session cap is measured.
- **Every pull has a stall watchdog** (no frame for N s → kill the ffmpeg child → backoff); `-rw_timeout` on RTSP. Any looping source resets its last-yielded PTS on wrap and never busy-loops the CDN while waiting for the wrap.
- **One time base**: every sighting and event carries `stream_time`, `wall_time`, `clock_source` and `provenance` (`docs/api.md` B6). RTSP: pull start + PTS, `clock_source = rtsp-live`. HLS: the shared recording timeline. Cooldowns and dedupe keyed on stream time, with an upper bound.
- **The DirectML detector session is not thread-safe**: one lock around `session.run()`; pre/post-processing parallel. PaddleOCR: PP-OCRv5_mobile det/rec, `enable_mkldnn=False` on CPU, a lock around init + predict, a per-track OCR budget (≥1.5 s between reads per track, ≤2 crops per frame, largest first). `docs/sandbox-findings.md` §7 has the crash reports.
- **The cascade**: motion gate (MOG2, reset on `stream_restart`) → YOLOX-S on the ROI-masked frame → vehicle crop → upscale to ~400 px wide (≤4×) + CLAHE → OCR on the crop, **never a full frame** → structural plate filter (Indian `SS DD L{1,3} NNNN` and BH-series `YY BH NNNN LL`, ambiguity-coerced, one module) → normalised + raw stored, 60 s per-plate-per-camera dedupe, ~2 KB crop with forward-slash paths. Skip boxes in the top ~5 % of the frame (burned-in caption). Reads < 8 characters are partial: stored, never alerted.
- **OCR consensus per track**, never a first-read latch; tracker matches on vehicle superclass so car↔truck flips keep one track; per-class NMS.
- **Persist before you match**: `record_sighting` commits, then the cached-watchlist match runs (exact → ambiguity map → confusion-weighted fuzzy, ≥ 8 chars), then the alert row commits, then anything broadcasts. 5-minute per-plate-per-camera cooldown.
- **Database writes** go through a single writer thread (`BEGIN IMMEDIATE`); object events are batched and best-effort; a locked write skips one frame, never ends the pull.
- Zone edits hot-reload via the supervisor poll; the watchlist cache refreshes every poll (10 s).
- **Measure, don't assume**: the supervisor writes `data/worker_stats.json` every 10 s (sustained fps, motion-skip rate, detections/min, sightings per camera, uptime). The HLD's `[measured]` rows come from a **10-minute** run of this file, after thermal settling.
- Licensing: YOLOX / RT-DETR and PaddleOCR only (Apache-2.0). Never Ultralytics; never copy ByteTrack's `kalman_filter.py`; never `open-image-models` plate weights. No training or fine-tuning.
- Model weights and the ffmpeg build are checksum-pinned. Model files download to a repo-controlled path, not the user profile, where possible.
