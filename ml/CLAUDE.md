# ml/ — layer rules

The worker process: one thread per active camera plus a supervisor. Owns frame acquisition (RTSP via an ffmpeg pipe with a stream-copied local HLS tee; the HLS VOD reader with AES-128 decrypt; the local replay source), the time base, the motion gate, the detector, the tracker, OCR, plate normalisation, sighting persistence, the cached watchlist match, object and zone events, and the stats snapshot. Reads the root `CLAUDE.md` first; these rules add to it. **Read `docs/feed-rules.md` and `docs/sandbox-findings.md` in full before writing a frame source.**

## Rules that bite this layer

- **The nine required behaviours of the frame source** (`docs/feed-rules.md`, last section) are the acceptance test: transport from the registry; credentialed URL built in memory, email percent-encoded, never logged unmasked; `FrameTick(frame, pts_ms, stream_time, wall_time, clock_source, restart)` ticks (the fresh build's form of the feed-rules' `(frame, pts_ms, wall_clock_utc)` tuple); sampling by dropping on PTS, never by sleeping; inter-frame gaps tolerated; decoder warnings at DEBUG; jittered backoff `2 s · 2^n · random(0.5, 1.5)` capped at 30 s with the anchor reset on reconnect; loop discontinuity → `stream_restart`; capture released in `finally`. The previous build's four checks (P2.1 in `docs/reference/old-build/P2-anpr.md`) still apply: 100 monotonic frames; ~180 frames in 60 s at 3 fps with a ~60 s PTS span; reconnect with visibly growing jittered delays; join warnings logged, loop continues.
- **One pull per camera** — the live wall is served from this process's tee, never a second connection. Active tier ≤ 6 until the RTSP session cap is measured.
- **Every pull has a stall watchdog** (no frame for N s → kill the ffmpeg child → backoff); `-rw_timeout` on RTSP. Any looping source resets its last-yielded PTS on wrap and never busy-loops the CDN while waiting for the wrap.
- **One time base** (decision F13): every sighting and event carries `seen_at` (= the stream-time instant), `wall_time`, `clock_source` and `provenance`. RTSP: `seen_at = wall_time = pull_start + PTS`, `clock_source = rtsp-live`. HLS/harvest: `seen_at` from the shared recording timeline (`backend/core/timeline.py`, epoch per decision F29). Replay-transport reads carry `clock_source = replay`, `provenance = test`, and the soak runs on `data/soak.db` (F26). Cooldowns and dedupe keyed on `seen_at`, with an upper bound.
- **The DirectML detector session is not thread-safe**: one lock around `session.run()`; pre/post-processing parallel. PaddleOCR: PP-OCRv5_mobile det/rec, `enable_mkldnn=False` on CPU, a lock around init + predict, a per-track OCR budget (≥1.5 s between reads per track, ≤2 crops per frame, largest first). `docs/sandbox-findings.md` §7 has the crash reports.
- **The cascade**: motion gate (MOG2, reset on `stream_restart`) → YOLOX-S on the ROI-masked frame → vehicle crop → upscale to ~400 px wide (≤4×) + CLAHE → OCR on the crop, **never a full frame** → structural plate filter (Indian `SS DD L{1,3} NNNN` and BH-series `YY BH NNNN LL`, ambiguity-coerced, one module) → normalised + raw stored, 60 s per-plate-per-camera dedupe, ~2 KB crop with forward-slash paths. Skip boxes in the top ~5 % of the frame (burned-in caption). A read that is not structurally `full` is partial: stored, never alerted, never fuzzy-matched (`docs/api.md` §6).
- **OCR consensus per track**, never a first-read latch; tracker matches on vehicle superclass so car↔truck flips keep one track; per-class NMS.
- **Persist before you match**: `record_sighting` commits, then the cached-watchlist match runs (exact → ambiguity map → confusion-weighted fuzzy, both sides structurally `full`), then the alert row commits, then anything broadcasts. 5-minute per-plate-per-camera cooldown, derived from the `alerts` table.
- **Database writes** go through the supervisor's single writer thread (`BEGIN IMMEDIATE`): sightings and alerts are awaited jobs, object events are async batches (decision F34); a DB error never ends a pull — log, skip the frame, continue.
- Zone edits hot-reload via the supervisor poll; the watchlist cache refreshes every poll (10 s).
- **Measure, don't assume**: the supervisor writes `data/worker_stats.json` every 10 s (sustained fps, motion-skip rate, detections/min, sightings per camera, uptime). The HLD's `[measured]` rows come from a **10-minute** run of this file, after thermal settling.
- Licensing: YOLOX / RT-DETR and PaddleOCR only (Apache-2.0). Never Ultralytics; never copy ByteTrack's `kalman_filter.py`; never `open-image-models` plate weights. No training or fine-tuning.
- Model weights, mediamtx and the ffmpeg build are checksum-pinned in the root `CHECKSUMS.txt`. Model files download to a repo-controlled path, not the user profile, where possible. ffmpeg/ffprobe only through `backend.core.config.ffmpeg()` / `ffprobe()`.

## Package layout (decision F12)

`ml/ingest/` — `__init__.py` (`for_camera` dispatch on `transport`), `base.py` (FrameTick, FrameSource, PTS sampler), `replay.py`, `rtsp.py`, `hls_vod.py` (S4.2). `ml/anpr/` — `motion.py`, `detect.py`, `track.py`, `ocr.py`, `pipeline.py`, `sightings.py`. `ml/analytics/` — `events.py`, `zones.py`. `ml/worker.py`, `ml/supervisor.py`, `ml/__main__.py`. `ml/tools/` — `fetch_models.py`, `smoke_rtsp.py`, `harvest.py`. Imports shared code from `backend.core` (plates, matcher, alerts, db, config, timeline). Run from the repo root: `python -m ml` — where `python` is **`.venv/Scripts/python`** (plain `python` in Git Bash is Anaconda and has none of these packages; `docs/tasks.md` protocol step 5).
